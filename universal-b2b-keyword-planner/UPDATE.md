# V2.0 更新说明

- 最终目标已按用户后续确认收束为：**一个核心词＋20个有效细分词**。先做简短框架分析，最后用 `外文关键词｜中文含义` 逐行导出；不再交付 L3/P0/P1/P2 独立清单、五部分表格或重复汇总。
- 适用对象扩展到实物产品与专业服务；行业采购/委托用语仍可作为细分候选，但仅在同类别、有能力依据且表达自然时保留。类别、真实性、同义重复、地域语言和排除规则继续用于质量筛选。
- 从用户给出的办公室隔断、声学舱、隔音舱、eMTB 与涉外诉讼示例归纳了边界：相邻产品不能凑词，企业业务模式不能擅自替换产品核心词，广义服务不能全部塞进单一服务核心词，参数/性能/法律专项能力需要资料核实。
- 五个原验收产品使用明确标为合成资料的输入，均生成 1 个核心词与 20 个细分词，并通过数量、去重、排除和格式检查。五个用户示例用于边界测试；缺少型号或服务证据时不假装已经获得合格 20 词。
- 当前工作区原本是空的未提交 Git 仓库；本机常用 Skill 目录及已连接的相关 GitHub 仓库均未找到 `universal-b2b-keyword-planner` 原文件。本次按用户需求和后续纠正重建，无法声称逐行继承旧版。
- 最新优化按客户的推广重点确定核心词范围，按买家选购需求筛选通用品类词和品牌型号词。导出示例使用纯文本块保留换行。
- 开发工作区的 `.agents/skills/universal-b2b-keyword-planner`（Codex）及 `.claude/skills/universal-b2b-keyword-planner`（Claude Code）是指向同一份 Skill 包的目录符号链接。Codex 格式验证已通过；本机未安装 Claude Code CLI，因此只检查了 Claude Code 的结构与路径，未做运行时调用。
- 未加入 SEO 页面、网站架构、Title/Meta、内容生成、GEO、竞品、监控、Dashboard、API、发布或 SaaS 功能。
